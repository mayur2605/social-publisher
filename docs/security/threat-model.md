# Security threat model

Version 1.0 · 2026-09-22 · Scope: code baseline `7265f91` and planned Railway deployment

This is a source-based design review, not a penetration-test certificate. Existing controls below are identifiable in code; remaining risks require the named tests or engineering work before release. Roles must be assigned by the product owner.

## Assets and trust boundaries

Protect creator identity/session, private source video, OAuth access/refresh tokens, app and encryption secrets, signed upload/stream capabilities, caption/schedule metadata, remote publication identity, Stripe state, usage allowance, and backups.

Boundaries are browser ↔ web/API; web/worker ↔ PostgreSQL; web/worker ↔ external OAuth/Drive/social/Stripe endpoints; platform fetcher ↔ signed media gateway; developer/CI ↔ deployed secrets; and backup/restore ↔ live scheduling. Threat actors include unauthenticated callers, another signed-in creator, a holder of a leaked capability, a compromised browser/dependency/operator credential, and malfunctioning or adversarial remote responses. Do not assume authenticated input or provider response data is safe by origin alone.

## Assurance plan

Existing tests in `tests/security.test.ts`, `integration.test.ts`, `platforms.test.ts`, and `billing.test.ts` cover parts of SEC-01–SEC-04 and SEC-07–SEC-08. Mock protocols do not prove provider policy compliance, deployed edge behavior, or resilience under live account revocation. Execute applicable [V-01–V-12](../lifecycle/05-validation.md), including both successful and rejected requests, before closing risks.

Add targeted adversarial cases for provider redirects/unexpected hosts, body streaming past a false Content-Length, repeated media ranges, XSS-like captions/account labels, callback replay, duplicate post creation after lost responses, and restore snapshots older than remote acceptance. Use only owned test environments and accounts; avoid placing active secrets in evidence.

For each SEC item record environment, commit, reproduction, controls exercised, result, residual impact, decision owner, and evidence reference. Critical authorization, secret leakage, uncontrolled duplicate publication, and accounting defects block release. A proposal or unexecuted test is not closure.

## Data access, incident response, and change triggers

Restrict database, provider, hosting, source-code, and backup access independently. Never grant support access to raw tokens for convenience. Logs use internal IDs and coarse error classes; redact query-string capabilities at infrastructure layers as well as application layers. Test actual alert delivery and revocation/rotation recovery.

Use the [incident procedure](../lifecycle/08-production-operations.md) for containment and recovery; preserve remote identifiers and reconcile before restarting dispatch. Revisit this model when adding a provider, changing OAuth scopes, auth library/configuration, media delivery, key handling, billing mode, deletion behavior, or deployment topology. No new security controls are installed by this document alone.
